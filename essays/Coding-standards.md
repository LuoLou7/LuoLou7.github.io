 When creating software, one of the goals is for the software to be repeatable, and it can be achieved by following coding standards. Coding standards keep the code clean, avoiding common mistakes, improving readability, and making it easy to maintain. Working with ESLint, I notice that there are a lot of coding standards rules that I break when coding and does not catch. Although getting rid of ESLint errors, especially when there are a lot of them and going over little details can be tedious, it is so much more beneficial in the long run to write clean code. The more I use ESLint, the easier it has been for me to catch my mistakes instantly and also easier to follow JavaScript coding standards. 
 Coding standards not only make your code readable and easy to maintain, but they can also help keep your code secure. Secure coding practices are non-negotiable when building applications, as they prevent security vulnerabilities. There are a lot of coding standards out there, and one of the popular coding standards for secure coding is probably OWASP. 
 Following necessary coding standards when creating software is crucial, especially in large-scale projects. It ensures consistent, secure, and readable code, making it efficient to work with.
